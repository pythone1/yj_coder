# 港股 AI/芯片主题研究终端开发任务

## 目标定位

把当前项目从单股票行情看板升级为“港股 AI/芯片主题智能研究终端”。

当前阶段不做自动交易。优先做信息聚合、主题跟踪、事件分析、AI 问答和异动监控。

重点关注对象：

- 壁韧/壁仞科技：名称和港股映射标的待确认，不能硬编码结论。
- MiniMax：公司本体、相关港股映射、产业链标的待维护。
- 智谱：当前项目已有 02513.HK 相关逻辑，但仍需抽象成可配置实体。

## P0：工程基础修复

### T0.1 移除硬编码密钥

任务：
- 删除 `data_engine.py` 和 `API测试.py` 中的明文 API Key。
- 改用环境变量 `ZHIPUAI_API_KEY`。
- 增加启动时缺少密钥的明确错误提示。

验收：
- 代码中搜索不到真实 Key。
- 未配置 Key 时程序不崩溃，返回清晰错误。

### T0.2 建立依赖和启动说明

任务：
- 新增 `requirements.txt`。
- 新增 `README.md`，说明启动方式、环境变量、端口、主要文件职责。

验收：
- 新机器按 README 能启动行情看板。

### T0.3 修复 RAG 构建脚本

任务：
- 修复 `RAG.py` 中 `newspaper` 未导入问题。
- 修复 `os.environ = ZHIPU_API_KEY` 错误。
- 新闻抓取失败时保留可用行情文本，不终止整个构建。

验收：
- `RAG.py` 能生成或更新 `knowledge_base/zhipu_stock.index` 和 `zhipu_chunks.pkl`。

## P1：多标的与实体配置

### T1.1 新增实体配置文件

任务：
- 新增 `entities.yaml`。
- 配置公司、股票代码、关键词、别名、产业链分类。

建议结构：

```yaml
entities:
  zhipu:
    display_name: 智谱
    stock_codes:
      - 02513.HK
    keywords:
      - 智谱
      - 智谱AI
      - GLM
  minimax:
    display_name: MiniMax
    stock_codes: []
    keywords:
      - MiniMax
      - 海螺AI
  biren:
    display_name: 壁仞科技
    stock_codes: []
    keywords:
      - 壁仞
      - 壁仞科技
      - Biren
```

验收：
- 新增关注对象不需要改 Python 源码。

### T1.2 行情引擎支持多股票

任务：
- 将 `STOCK_CODE_NUM = "02513"` 改成从配置读取。
- 输出 JSON 改为多标的结构。

建议输出：

```json
{
  "stocks": {
    "02513.HK": {
      "realtime": {},
      "intraday": {},
      "kline": {},
      "technical": {}
    }
  }
}
```

验收：
- 前端可切换至少 2 个配置标的。

## P2：事件数据库

### T2.1 新增 SQLite 事件库

任务：
- 新增 `events.db`。
- 表结构包含：时间、来源、标题、正文摘要、URL、实体、事件类型、重要性、影响方向。

事件类型：
- 模型发布
- 融资
- 上市进展
- 合作订单
- 芯片进展
- 财报公告
- 股价异动
- 监管风险

验收：
- 新闻或公告可以结构化入库。
- 同一 URL 不重复入库。

### T2.2 事件抽取器

任务：
- 从新闻标题/正文中抽取关联实体和事件类型。
- 初期用关键词规则，后续再接 AI 分类。

验收：
- 一条新闻可以自动打上实体和事件类型。

## P3：RAG 问答升级

### T3.1 `/chat` 接入本地知识库

任务：
- 用户问题先向量化。
- 查询 FAISS。
- 取 Top K 文档片段。
- 拼接实时行情、技术指标、最近事件。
- 再调用 GLM 回答。

验收：
- 回答能引用本地知识库内容，而不是只依赖联网搜索。

### T3.2 问答输出格式标准化

任务：
- 固定输出结构：
  - 核心结论
  - 关键证据
  - 行情/技术面
  - 风险点
  - 观察点

验收：
- 问“智谱今天为什么涨”时，返回结构稳定。

## P4：专业前端改造

### T4.1 改成研究终端布局

任务：
- 左侧：观察池。
- 中间：分时/K线/指标。
- 右侧：AI 分析。
- 底部：事件时间线。

验收：
- 不再是单股票页面。
- 能切换公司和股票。

### T4.2 增加主题热度榜

任务：
- 展示智谱、MiniMax、壁仞等实体的热度分。
- 分数由新闻数量、重要性、股价强度、成交额变化组成。

验收：
- 前端显示每个主题的分数和变化方向。

## P5：异动监控

### T5.1 行情异动规则

任务：
- 检测涨跌幅异常。
- 检测成交额放大。
- 检测突破 MA20、前高、布林上轨。
- 检测 MACD 金叉/死叉。

验收：
- 触发异动时写入事件库。

### T5.2 AI 异动解释

任务：
- 异动触发后，自动汇总最近新闻、公告、技术指标。
- 生成一句原因假设和风险提示。

验收：
- 前端显示“异动原因候选”，并标注不是确定事实。

## P6：每日研究简报

### T6.1 收盘后生成 Markdown 简报

任务：
- 生成 `reports/YYYY-MM-DD.md`。
- 包含：
  - 今日主题排名
  - 重点异动
  - 重要事件
  - 技术面摘要
  - 明日观察点

验收：
- 每天可以生成一份可读简报。

## 推荐执行顺序

1. P0：先修安全、依赖、RAG 脚本。
2. P1：配置化多标的。
3. P3：把本地 RAG 接入 `/chat`。
4. P2：事件数据库。
5. P4：前端专业化。
6. P5：异动监控。
7. P6：每日简报。

## 第一轮开发建议

第一轮只做 4 件事：

1. 新增 `entities.yaml`。
2. 改造 `data_engine.py`，支持从配置读取多个标的。
3. 修复密钥和 RAG 明显错误。
4. 前端增加观察池切换。

完成后，项目会从“单股演示”变成“可扩展研究终端原型”。
