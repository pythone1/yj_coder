一、AI Agent 经典架构总览

面向闭环控制的“感知 - 思考 - 行动”核心三要素体系

INPUT SYSTEM
01 / 感知层 (Perception)
  • 多模态输入解析：支持文本、图像、语音、视频等多模态特征提取与语义交叉理解。
  • 具身环境融合：可对接激光雷达、IMU、触觉等各种物联网与机器人传感器数据。
  • 主动感知流：实现定时轮询拉取（如系统日志或视频帧），由被动响应转为主动感知。
DECISION CORE
02 / 核心大脑 (Brain)
  • 目标分解规划：将模糊的顶层大目标逐步拆解为清晰的子任务节点，并支持动态调整。
  • 记忆存取召回：结合短期会话缓存与长期向量数据库，秒级召回关联背景事实。
  • 意图决策引擎：根据上下文与 Prompt 边界，推理出最佳下一步策略。
EXECUTION UNIT
03 / 执行层 (Action)
  • 结构化 API 调用：通过大模型 Function Calling 输出标准的 JSON 参数结构。
  • 代码执行器：动态编写 Python 并在封闭隔离的沙盒中运行计算与数据可视化。
  • 环境反向输入：执行结果作为新的观测数据重传给大脑，构成闭环自适应反馈。

二、大脑核心之：Planning 规划与推理技术

从一步直觉式回复走向深度搜索与反思反馈控制

经典思维路径拓扑 (From Chain to Tree)
  • 思维链 (Chain of Thought, CoT)：诱导模型逐步写出推理链路，降低逻辑断层，显著提高数值计算与逻辑推理准确率。
  • 思维树 (Tree of Thoughts, ToT)：在多步规划中引入搜索树，生成多个解题方向，结合深度/广度优先搜索进行回溯评估。
  • 蒙特卡洛树搜索 (MCTS)：大模型作为启发式估值器，配合 MCTS 进行多轮 Rollout 仿真，用以在超大行动空间下计算最优决策链。
动作与反思闭环机制 (Act & Reflexion)
  • ReAct 协同工作流：将『Thought（思考） $\rightarrow$ Action（动作） $\rightarrow$ Observation（观察）』交替演进。思考指挥动作，动作改变环境产生观察，观察修正思考。
  • Reflexion 自我修正网络：当任务运行报错或偏离目标时，由独立的 Evaluator Agent 提取执行日志进行自我反思，将失败教训编码为反思向量注入短期上下文，实现零参数微调自适应进化。

三、大脑核心之：Memory 记忆机制与知识存取

融合短期序列关联与长期外挂多维检索的双轨记忆架构

短期记忆：会话上下文与状态机
  • 滑动会话窗口：为防止长对话撑爆 Token，使用滑动窗口或自动触发“总结 Agent”对历史轨迹进行特征聚合压缩。
  • 严格系统状态机：利用后端强状态表记录业务流核心字段（如支付金额、履约状态），保证业务流程不随 LLM 的意图漂移而失控。
  • Prefill KV Cache 共享：优化高并发请求下 System Prompt 与长模版的显存消耗与耗时。
长期记忆：向量数据库与高精 RAG
  • 混合检索 (Hybrid Search)：将 Dense 稠密向量的语义检索与 Sparse 稀疏向量（BM25）的字面碰撞相结合，对中英混合和缩写具备更强召回率。
  • 两阶段检索管道：第一阶段利用 ANN 算法从向量库秒级筛选 Top-K 节点；第二阶段采用双向交互的 Cross-Encoder Reranker 模型剔除弱关联噪声。

四、工具调用与沙盒安全 (Actions & Tool Integration)

打通大模型与外界操作系统的矢量互通与安全防护隔离

工具描述与匹配
  • JSON Schema 定义：用极其标准的 JSON Schema 注册工具名称、参数类型及业务说明。
  • 动态意图路由：计算 Query 向量与所有工具描述向量的相似度，动态分配最切合的 API。
代码解释器
  • 动态脚本编写：大模型遇到高阶复杂计算或数据分析时，主动在内存中写出 Python 脚本。
  • Traceback 自检循环：运行出错时，错误信息反传，驱动大模型自我调试，直至成功运行。
隔离沙盒与防护
  • Docker 隔离机制：运行代码必须放置在一次性、轻量的 Docker 容器中。
  • E2B 运行时：采用定制化的云端或本地 Agent 执行环境，严格封锁宿主机系统，防范危险脚本的破坏。

五、多智能体协同与编排架构 (Multi-Agent Systems)

从单兵作战演进为有组织、有状态的多角色生产线网络

多智能体协同范式分类
  • 主从模型 (Manager-Worker)：Manager 分解目标，Worker 执行具体任务并向 Manager 汇报，最后由 Manager 统筹合并与质检。
  • 对等辩论模型 (Peer-to-Peer & Debate)：设定不同角色 Agent。例如『开发 Agent』写码，『测试 Agent』挑刺，『安全 Agent』合规审核，在消息总线上异步协作博弈。
主流 Agent 开发框架剖析
  • LangGraph (基于状态图)：将智能体工作流建模为有向图。核心是定义共享的全局 State，支持循环、条件分支和人类干预环节（Human-in-the-loop），具备极高工程可控度。
  • CrewAI (角色团队编排)：定义 Role、Task 和 Crew，能够快速模拟职场多人分工流水线，上手门槛低。

六、智能体落地演进路线与行业挑战

从低阶提示词包装，向深度微调、高并发状态编排迈进

STAGE 1: STANDARD
L1 - RAG与工具浅层封装
  • 基于 LangChain、LlamaIndex 快速搭建本地知识库问答。
  • 模型多为一次性对话，缺乏反思回溯，容易陷入指令死循环。
  • 适合简单客服、基础知识库检索。
STAGE 2: ADVANCED
L2 - 复杂状态工作流编排
  • 引入 LangGraph 进行多角色协同图设计，支持状态持久化与回溯。
  • 引入 Human-in-the-loop (人工审批) 以及代码解释器隔离沙盒。
  • 适合复杂合同审核、软件自动化测试。
STAGE 3: AUTONOMOUS
L3 - 垂直微调与完全自主进化
  • 通过轨迹与 Function Calling 微调强固化底层大模型能力，摆脱冗长 Prompt。
  • 结合长时反思日志，利用 RL 算法实现策略优化自主学习。
  • 适合高并发、全自动的特定岗位数字员工。
